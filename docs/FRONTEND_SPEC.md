# Спецификация фронтенда (Jira-подобный, мультипроектный)

Снято с прототипа (Lovable) вручную. Фронтенд — `frontend/`, бэкенд — FastAPI (`webapp/`).

## Стек
React 18 + TypeScript + Vite, TanStack Router (file routes) или React Router, TanStack Query,
Tailwind CSS (shadcn-подобные компоненты, без внешних UI-китов), шрифт «Golos Text» (Google Fonts),
иконки lucide-react. Тёмная тема через класс `.dark` на `<html>`.

Стиль: тёмно-зелёный сайдбар, светло-серо-зелёный фон, белые карточки с тонкой рамкой и radius 8px,

## Каркас
- **Левый сайдбар** (тёмно-зелёный, сворачиваемый, кнопка «Свернуть» внизу):
  логотип-плашка «B» + «Requirements · Review platform»; «Все проекты»; поле «Поиск проекта…»;
  список проектов (аватар-плашка из 2 букв ключа, название, звезда избранного); у активного проекта
  вложенное меню: Обзор, Прогоны, Дефекты, Требования, Трассируемость, Контекст, Тест-кейсы, Настройки
  (активный пункт — золотой текст + подсветка); внизу списка «+ Создать проект» (золотой).
- **Верхняя панель**: глобальный поиск «Поиск: проекты, CARD-17, R-05…»; бейдж режима API
  («MOCK API» / «LIVE API»); «Ключ модели настроен: да/нет»; золотая кнопка «Новая проверка»
  (ведёт на `/projects/$key/runs?new=true`); переключатель темы; аватар пользователя.
- Хлебные крошки над заголовком: «Проекты / CARD / Дефекты / CARD-2».

## Маршруты
| Путь | Страница |
|---|---|
| `/` | Все проекты |
| `/?create=true` | Модалка создания проекта |
| `/projects/$key` | Обзор |
| `/projects/$key/runs` (`?new=true`) | Прогоны (+ панель новой проверки) |
| `/projects/$key/runs/$runId` | Отчёт прогона |
| `/projects/$key/defects` (`?d=KEY-N&view=board|list&фильтры`) | Дефекты + боковая панель дефекта |
| `/projects/$key/requirements` | Реестр требований |
| `/projects/$key/traceability` | Трассируемость |
| `/projects/$key/context` | Контекст проекта |
| `/projects/$key/testcases` | Тест-кейсы |
| `/projects/$key/settings` | Настройки |

## Страницы

### Все проекты
Заголовок «Все проекты», подзаголовок «Статическая проверка требований · ISO/IEC/IEEE 29148, IEEE 830»,
кнопка «+ Создать проект». Таблица: звезда (toggle избранного), КЛЮЧ (зелёный моно), НАЗВАНИЕ + описание,
ВЛАДЕЛЕЦ, ПОСЛЕДНИЙ ПРОГОН (дата, зелёная), РЕШЕНИЕ (бейдж), ОТКРЫТЫЕ CRITICAL (красное число).
Модалка создания: название, ключ (автогенерация из названия, 2–10 латинских заглавных), описание, владелец.

### Обзор проекта
Заголовок = название, строка «CARD · описание · владелец X», кнопка «Запустить проверку».
5 KPI-карточек: РЕШЕНИЕ (бейдж), ТРЕБОВАНИЙ, ОТКРЫТЫЕ ДЕФЕКТЫ, ОТКРЫТЫЕ CRITICAL (красным), COVERAGE %.
3 карточки с горизонтальными барами: «По серьёзности» (Critical/Major/Minor — красные бары),
«По статусу» (Открыт/В работе/Исправлен/Отклонён — зелёные), «По критериям» (золотые).
Карточка «Динамика прогонов» — вертикальные зелёные столбцы: число нарушений, подпись «#n» и дата.
Пустое состояние, если прогонов нет: CTA «Запустить первую проверку».

### Прогоны
Заголовок «Прогоны проверки», кнопки «Сравнить выбранные (0/2)» и «Новая проверка».
Панель новой проверки (раскрывается над таблицей при `?new=true`): Документ (select из документов проекта
+ пункт «Загрузить новый…» → drag&drop PDF/DOCX/MD/TXT до 10 МБ, создаёт документ или новую версию),
Версия (select «v3 · 2026-11-19»), Модель (select), золотая кнопка «Запустить»; чекбоксы «Учитывать контекст
проекта», «Генерировать тест-кейсы», «Доменная проверка».
Таблица: чекбокс (для сравнения, максимум 2), #n (зелёный, ссылка), ДОКУМЕНТ (имя + vN, ниже дата),
МОДЕЛЬ (моно), СТАТУС (queued/running с прогрессом %/done/error), ДЛИТ., ТРЕБ., НАРУШЕНИЙ (жирным),
COVERAGE, РЕШЕНИЕ (бейдж), АГЕНТ (короткий коммит, моно).
Запущенный прогон: живой прогресс по шагам (Загрузка → Сегментация → Проверка требований i/n →
Проверка набора → Контекст → Отчёт), опрос каждые 2 с.
Сравнение двух прогонов: исправлено / новое / осталось (списки дефектов).

### Отчёт прогона
Заголовок «Отчёт · прогон #3», подзаголовок «<документ> vN · <модель>». Кнопки экспорта: MD, HTML, DOCX,
JSON, «Печать». Вкладки (подчёркнутый активный таб): 1. Паспорт · 2. Нарезка требований · 3. Проверка
требований · 4. Проверка набора · 5. Сводка · 6. Итог · 7. Контекст и трассируемость · 8. Тест-кейсы.
1. Паспорт — 2-колоночная таблица «ключ — значение»: Документ, Стандарт, Модель, Версия агента,
   Требований, Покрытие, Дата, Длительность, Вызовов LLM, хэш файла.
2. Нарезка — таблица с поиском: ID в отчёте, ID в документе, Раздел, Строка, Формулировка, Цитата.
3. Проверка требований — карточки: «R-02 · 2.3 Шаблоны», цитата в «ёлочках», справа ключ связанного
   дефекта (CARD-31, ссылка); ряд чипов-критериев (✓ зелёный OK / ✕ красный нарушение / серый Н/П);
   зелёная плашка «Предлагаемая переформулировка» с кнопкой копирования; список нарушений.
4. Проверка набора — для каждого противоречия две колонки-цитаты с красной левой рамкой и ID над ними,
   под ними объяснение; ниже вердикты по критериям набора и отсутствующие разделы.
5. Сводка — счётчики, бары по серьёзности и критериям, критичные дефекты тремя группами:
   Непроверяемые / Противоречивые / Неполные.
6. Итог — крупный бейдж решения, обоснование, нумерованный «Что исправить в первую очередь» (топ-7).
7. Контекст и трассируемость — матрица ЦЕЛЬ × ТРЕБОВАНИЯ × КРИТЕРИИ ПРИЁМКИ × API, ячейки «Не покрыто»
   красным на розовом фоне, непокрытая цель — красным текстом; ниже конфликты с контекстом (две цитаты:
   документ и файл контекста).
8. Тест-кейсы — как на странице тест-кейсов.

### Дефекты (главная Jira-страница)
Заголовок «Дефекты», «N найдено»; переключатель «Доска / Список».
Фильтры (в карточке): поиск «Ключ или текст», Серьёзность, Критерий, Тип (Внутренний / Конфликт с
контекстом / Доменный риск), Статус, Исполнитель, Прогон, Раздел; кнопки «Сбросить», «Сохранить фильтр»
(сохранённые фильтры появляются чипами). Фильтры и открытый дефект — в URL (`?d=CARD-2`).
Доска: 4 колонки ОТКРЫТ / В РАБОТЕ / ИСПРАВЛЕН / ОТКЛОНЁН со счётчиками; карточка: чекбокс, ключ (зелёный
моно), бейдж серьёзности, заголовок, критерий, исполнитель; drag&drop между колонками меняет статус.
Массовые действия при выборе чекбоксов: сменить статус, назначить исполнителя.
Список: таблица с теми же полями + требование, раздел, прогон; сортировка, пагинация.
Боковая панель дефекта (справа, ~45% ширины, закрывается ✕/Esc): ключ, серьёзность, статус-бейдж, заголовок;
select «Статус», select «Исполнитель»; Критерий, Тип, Требования (ссылки R-xx), «Найден в: прогон»;
«Цитаты» — жёлтая плашка с цитатой и 📍 место (раздел, строка); «Объяснение»; «Исправление» (зелёная
плашка); красная контурная кнопка «Отклонить как ложное срабатывание» (спрашивает причину);
«Комментарии (n)» + поле и кнопка «Отправить»; «История» (дата · автор · действие).

### Требования
Заголовок «Требования», «Реестр последнего прогона»; поиск; чекбокс «Только с нарушениями».
Таблица: ID (зелёный моно), РАЗДЕЛ, ФОРМУЛИРОВКА, ВЕРДИКТЫ (ряд цветных точек по критериям — зелёная OK,
красная нарушение, серая Н/П, с tooltip), ДЕФЕКТЫ («2 →» ссылка на отфильтрованные дефекты).

### Трассируемость
«Цели × Требования × Критерии приёмки × API. Красным — непокрытое.» Матрица как во вкладке 7 отчёта.

### Контекст проекта
Справа сверху select типа (Паспорт проекта / Глоссарий / Каталог систем / SLA / Политики ИБ / Прочее) и
кнопка «Загрузить». Слева список файлов-карточек (имя, «тип · vN · дата», иконка удаления).
Справа «Предпросмотр: <файл>» (моно-текст) и «Извлечено из паспорта»: Цель / Скоуп / Ограничения и др.

### Тест-кейсы
Кнопка «Экспорт CSV». Сетка 2 колонки карточек: «TC-CARD-001», справа ID требования; «Проверка: …»;
нумерованные шаги; зелёная плашка «✓ ожидаемый результат».

### Настройки
Карточка: Модель по умолчанию (select), Размер пакета требований, Порог «можно начинать разработку»:
max critical (число), «API-ключ модели: Ключ настроен: да/нет».
Карточка «Включённые критерии» — чекбоксы. Карточка «Участники и роли» — имя + select роли
(Аналитик/Тестировщик/Архитектор), добавить участника. Кнопки «Сохранить» и «Удалить проект» (красная, с подтверждением в модалке приложения, не `confirm()`).

## Общее
Скелетоны загрузки, пустые состояния, понятные ошибки (в т.ч. «Исчерпана квота модели»), toast-уведомления,
клавиатурная навигация, aria-атрибуты, адаптив до 375px (сайдбар превращается в выезжающее меню).
Клик по R-xx / KEY-N в любом месте открывает требование / дефект. API-ключ никогда не отображается.
